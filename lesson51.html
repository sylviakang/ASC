1專案全貌

GyroQuiz 最終有 11 個程式檔、6 個測試檔，合計約 800 行。每個檔案都是哪幾堂學的：

檔案哪幾堂負責
MainActivity.kt20入口：鎖直向、套主題、呼叫 GyroQuizApp
App.kt22、26、33、35、37四頁換頁、讀題、存檔、成績交接
Common.kt23共用的 BackBar
HomeScreen.kt21Logo、標題、兩個按鈕
Question.kt25–26Question 資料類別、讀 JSON
QuizLogic.kt30、33、39–46GameResult 與所有「純計算」函式
Formats.kt31、33mm:ss、12m 11s、日期格式
QuizScreen.kt24、27–32、40–49答題頁：計時、陀螺儀、游標、狀態機
ResultScreen.kt33結算頁
RecordDb.kt34–36SQLite 建表、寫入、讀取
RecordsScreen.kt37遊玩紀錄清單
小技巧
比賽時就照這個順序寫：先 MainActivity、App、四頁空殼（流程通）→ 讀題與答題（點選版）→ 計時與結算 → 資料庫 → 陀螺儀與停留選答。每一步都能 Run，隨時有可以交的版本。

2資料怎麼流動

資料流
Questions.json ──loadQuestions──▶ allQuestions (App)
                                       │
                                       ▼
          HomeScreen ──新遊戲──▶ QuizScreen(allQuestions)
              ▲                        │ onFinish(GameResult)
              │                        ▼
              │                App: db.insert(r); result = r
              │                        │
              └────回首頁──── ResultScreen(result)

          HomeScreen ──遊玩紀錄──▶ RecordsScreen(db.getAll())

原則：資料由上往下傳（參數），事件由下往上傳（callback）。各頁不自己讀檔、不自己存檔，都交給 App.kt。

3QuizScreen 的六個區塊

最長的 QuizScreen 可以分成六段，每段開頭都有註解 // ---------- … ----------：

區塊做什麼關鍵
題目與狀態抽 10 題、index、顏色、錯題、退出對話框remember、mutableSetOf
計時每 0.1 秒累加、進背景暫停LaunchedEffect(resumed)、DisposableEffect
陀螺儀角速度積分成 angleX / angleYSensorEventListener、integrate
選項位置與游標量 4 格、算游標位置、夾在區域內、找出 hoveredonGloballyPositioned、cursorPos、clamp、hitIndex
停留選答與狀態3 秒選答、答錯鎖 5 秒、答對等 2 秒Phase、兩個 LaunchedEffect
畫面上方列、進度條、題目、2×2 選項、Canvas 游標、雙擊校正Box 疊層、drawArc、detectTapGestures

4為什麼要把計算拆到 QuizLogic.kt

nextColorIndexes、integrate、cursorPos、clamp、hitIndex、dwellProgress 都是「給數字、回數字」的純函式，不碰畫面、不碰 Android。好處：

  • 可以寫單元測試，不用開模擬器就知道對不對。
  • QuizScreen 讀起來像在說故事（cursorPos、clamp、hitIndex），細節藏在函式裡。
  • 比賽題本若修改規則（例如停留 2 秒），只要改一個地方。
