1問題：游標在哪一格上

要做「停留 3 秒選答」，第一步是隨時知道游標中心落在哪個選項裡：0～3，或是 -1（落在格子之間的縫）。

判斷「點在不在矩形裡」，C 語言就會寫：

條件
left <= x && x <= right && top <= y && y <= bottom

4 格逐一檢查，第一個符合的就是答案。

2hitIndex

QuizLogic.kt
// 游標中心落在哪一個選項的範圍內，都不在就回傳 -1
// rects 每一項是 floatArrayOf(left, top, right, bottom)
fun hitIndex(x: Float, y: Float, rects: List<FloatArray>): Int {
    for (i in rects.indices) {
        val r = rects[i]
        if (x >= r[0] && x <= r[2] && y >= r[1] && y <= r[3]) return i
    }
    return -1
}
  • rects.indices：0 until rects.size。
  • r[0]=left、r[1]=top、r[2]=right、r[3]=bottom（第 41 堂存的順序）。
  • 找到就 return i；迴圈跑完都沒有 → -1。
C#
for (int i = 0; i < 4; i++) {
    var r = rects[i];
    if (x >= r[0] && x <= r[2] &&
        y >= r[1] && y <= r[3]) return i;
}
return -1;

3測試

畫一張 2×2、每格 100、縫 10 的假選項來測：

HitTest.kt
class HitTest {
    private val rects = listOf(
        floatArrayOf(0f, 0f, 100f, 100f), floatArrayOf(110f, 0f, 210f, 100f),
        floatArrayOf(0f, 110f, 100f, 210f), floatArrayOf(110f, 110f, 210f, 210f)
    )

    @Test
    fun hit() {
        assertEquals(0, hitIndex(50f, 50f, rects))
        assertEquals(3, hitIndex(200f, 200f, rects))
        assertEquals(-1, hitIndex(105f, 50f, rects))   // 落在兩格中間的縫
    }
}
測試用的格子
  0      100 110     210
0 ┌──────┐   ┌──────┐
  │  0   │   │  1   │
100└──────┘   └──────┘
110┌──────┐   ┌──────┐
  │  2   │   │  3   │

4在畫面上用起來

QuizScreen.kt（cursorY 下面）
val hovered = if (ready) hitIndex(cursorX, cursorY, rects.map { it!! }) else -1
  • rects.map { it!! }：把 List<FloatArray?> 轉成 List<FloatArray>（ready 時保證不是 null）。
  • cursorX、cursorY 和 rects 都是 root 座標，可以直接比，不用扣 origin（扣 origin 只有畫在 Canvas 時才需要）。

先做一個暫時的效果確認判斷正確：被游標指到的選項加粗外框。

選項 Box 的 Modifier（background 後面）
.then(
    if (hovered == i) Modifier.border(4.dp, Color.Black, RoundedCornerShape(16.dp))
    else Modifier
)
補充
.then(…) 是「接上另一個 Modifier」。用 if 決定接 border 還是接一個空的 Modifier，這是 Compose 依條件加效果的常用寫法。第 48 堂的紅框、綠框也會用到。
