觀念講解

慢慢讀

1為什麼要拆

GyroQuiz 有 4 頁，每頁都有返回列、按鈕、文字。全部寫在一個函式裡會有幾百行，找不到東西也改不動。像 WinForms 把常用的一組控制項做成 UserControl，Compose 把畫面拆成小函式。

2有參數的元件

@Composable
fun BigButton(text: String) {
    Button(onClick = { }, modifier = Modifier.width(220.dp)) {
        Text(text, fontSize = 20.sp)
    }
}

// 使用
BigButton("新遊戲")
BigButton("再玩一次")

相同樣子的按鈕寫一次，用參數換文字。

3把「按下去要做什麼」也當參數

上面的按鈕按了沒反應，因為 onClick 是空的。但 BigButton 自己不知道按下去該做什麼，那是呼叫它的人才知道的事。所以把 onClick 也變成參數，型別是 () -> Unit（不收參數、不回傳東西的函式）：

@Composable
fun BigButton(text: String, onClick: () -> Unit) {
    Button(onClick = onClick, modifier = Modifier.width(220.dp)) {
        Text(text, fontSize = 20.sp)
    }
}

// 使用：呼叫的人決定要做什麼
BigButton("新遊戲", onClick = { Log.d("GQ", "開始遊戲") })
BigButton("遊玩紀錄") { Log.d("GQ", "看紀錄") }   // lambda 寫在括號外也可以

4狀態放在上層，往下傳

如果子元件需要顯示某個狀態，又需要改它，做法是：狀態放在上層，把「值」和「改它的方法」傳下去。這叫狀態提升（state hoisting）。

@Composable
fun ScoreBoard() {
    var score by remember { mutableIntStateOf(0) }       // 狀態在上層
    Column {
        ScoreText(score)                                  // 往下傳值
        AddButton(onAdd = { score += 10 })                // 往下傳「怎麼改」
    }
}

@Composable
fun ScoreText(score: Int) {
    Text("分數：$score", fontSize = 24.sp)
}

@Composable
fun AddButton(onAdd: () -> Unit) {
    Button(onClick = onAdd) { Text("+10") }
}
補充
GyroQuiz 就是這個結構：最上層的 GyroQuizApp 記住「現在在哪一頁」，每一頁收到 onNewGame、onBack 這類參數，按下時通知上層換頁（第 22 堂）。

5帶參數的事件

有時通知上層時要帶資料，例如「玩完了，成績是這樣」：

@Composable
fun FinishButton(onFinish: (Int) -> Unit) {
    Button(onClick = { onFinish(8) }) { Text("結束") }
}

// 上層
FinishButton(onFinish = { correct -> Log.d("GQ", "答對 $correct 題") })

(Int) -> Unit 表示「收一個 Int、不回傳」的函式。
