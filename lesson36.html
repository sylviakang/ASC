觀念講解

慢慢讀

1讀取的 SQL

SQL
SELECT correct, wrong, duration, end_time
FROM records
ORDER BY end_time DESC
片段意思
SELECT 欄位, 欄位要取哪些欄（* 代表全部）
FROM records從哪張表
ORDER BY end_time依結束時間排序
DESC由大到小 → 新的在前（ASC 是由小到大）
補充
這就是為什麼 end_time 存毫秒數字：數字越大越新，直接排序就對。如果存成 "05:45 PM" 字串就排不出來。

2Cursor：一列一列往下讀

rawQuery 回傳一個 Cursor（游標），想像成指向表格某一列的箭頭，一開始在第一列前面：

RecordDb.kt
fun getAll(): List<GameResult> {
    val list = mutableListOf<GameResult>()
    val c = readableDatabase.rawQuery(
        "SELECT correct, wrong, duration, end_time FROM records ORDER BY end_time DESC", null
    )
    while (c.moveToNext()) {
        list.add(GameResult(c.getInt(0), c.getInt(1), c.getInt(2), c.getLong(3)))
    }
    c.close()
    return list
}
  1. c.moveToNext()：箭頭往下一列，有資料回傳 true，沒有了回傳 false → 剛好當 while 條件。
  2. c.getInt(0)：取這一列第 0 欄。順序是 SELECT 後面寫的順序：0 correct、1 wrong、2 duration、3 end_time。
  3. end_time 是 Long，用 getLong(3)。
  4. 讀完一定要 c.close() 關閉。

注意
欄位編號從 0 開始。如果 SELECT 寫 *，第 0 欄會是 id，所有編號都要 +1，很容易錯。所以我們明確寫出要哪四欄。

3GameResult(…) 依順序填

GameResult(c.getInt(0), c.getInt(1), c.getInt(2), c.getLong(3)) 沒寫參數名稱時，依 data class 宣告順序填：correct、wrong、durationSec、endMillis。剛好和 SELECT 的順序一樣，這是故意安排的。

4先用 Log 確認

畫面下一堂做，今天先在 App.kt 進入紀錄頁時印出來：

App.kt（暫時）
Screen.RECORDS -> {
    val records = remember { db.getAll() }
    LaunchedEffect(Unit) {
        for (r in records) Log.d("GQ", "$r")
    }
    RecordsScreen(onBack = { screen = Screen.HOME })
}

Logcat 會印出 GameResult(correct=8, wrong=2, durationSec=731, endMillis=…)，第一筆是最新的那局。

補充
remember { db.getAll() }：進入紀錄頁時讀一次就好，不要每次重畫都查資料庫。
