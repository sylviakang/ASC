觀念講解

慢慢讀

1為什麼要有 null 安全

C# 的物件變數可以是 null，一不小心呼叫它的方法就會 NullReferenceException。Kotlin 規定：一般型別不能放 null，要放 null 必須在型別後面加 ?。

var name: String = "Amy"
// name = null          // 錯誤：String 不能是 null

var result: String? = null   // 加了 ? 才可以
result = "答對"
補充
GyroQuiz 的結算頁一開始還沒有成績，所以成績變數是 GameResult?，玩完一局才有值。

2使用可能是 null 的變數

對 String? 直接取屬性會出現紅字，因為它可能是 null。三種處理方式：

val result: String? = null

// 1. if 先檢查，檢查過後 Kotlin 就知道它不是 null
if (result != null) {
    println(result.length)
}

// 2. ?.  是 null 就不做，整個結果是 null
println(result?.length)      // null

// 3. ?:  是 null 時改用後面的值（貓王運算子）
println(result ?: "還沒作答")   // 還沒作答
C#
string s = null;
int? len = s?.Length;
string t = s ?? "預設";
Kotlin
val s: String? = null
val len = s?.length
val t = s ?: "預設"
注意
還有一個 !!（「我保證不是 null」），是 null 時一樣會閃退。不要用，除非你真的確定。

3找不到時回傳 null 的函式

很多 Kotlin 函式在「找不到」時回傳 null，例如：

val nums = listOf(3, 8, 1)
val big = nums.firstOrNull { it > 5 }    // 8
val huge = nums.firstOrNull { it > 100 } // null
println(huge ?: "沒有")

（{ it > 5 } 的寫法下一堂會解釋。）

4enum class：有限的幾種狀態

C# 有 enum，Kotlin 叫 enum class。GyroQuiz 用兩個 enum：「現在在哪一頁」和「答題狀態」。

C#
enum Screen { Home, Quiz, Result, Records }

Screen s = Screen.Home;
Kotlin
enum class Screen { HOME, QUIZ, RESULT, RECORDS }

var s = Screen.HOME
小技巧
Kotlin 的習慣是 enum 的值全部大寫。

5enum 搭配 when

when 判斷 enum 時，如果每一個值都寫到，就不用 else。少寫一個，Android Studio 會提醒你，非常適合防止漏掉某一頁：

enum class Phase { PLAYING, WRONG, CORRECT }

fun describe(p: Phase): String = when (p) {
    Phase.PLAYING -> "作答中"
    Phase.WRONG -> "答錯，鎖定 5 秒"
    Phase.CORRECT -> "答對，2 秒後下一題"
}

fun main() {
    var phase = Phase.PLAYING
    println(describe(phase))
    phase = Phase.WRONG
    println(describe(phase))
}
