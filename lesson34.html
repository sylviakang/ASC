1題本要求

每玩完一局，把成績存進 SQLite 資料庫；「遊玩紀錄」頁從資料庫讀出來，依結束時間新到舊排列。關掉 App 再打開，紀錄還在。

這個功能分四堂做：今天建表 → 35 寫入 → 36 讀取 → 37 顯示。

2資料庫是什麼

可以把資料表想成 Excel 的一張工作表，或 C 的「struct 陣列存到檔案裡」：

idcorrectwrongdurationend_time
1827311782467100000
21004021782470000000
  • 每一列（row）是一筆紀錄 = 一個 GameResult。
  • 每一欄（column）是一個欄位，有固定型別。
  • SQLite 是手機內建的小型資料庫，整個資料庫就是 App 裡的一個檔案 gyroquiz.db，不用另外裝伺服器。

3SQL：和資料庫說話的語言

今天只用到一句建表的 SQL：

SQL
CREATE TABLE records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    correct INTEGER,
    wrong INTEGER,
    duration INTEGER,
    end_time INTEGER
)
片段意思
CREATE TABLE records建立名為 records 的資料表
INTEGER整數（SQLite 的 INTEGER 可以放 Long）
PRIMARY KEY主鍵：每一列唯一的編號
AUTOINCREMENT自動 +1，新增時不用給 id
補充
SQL 的關鍵字大小寫都可以，習慣上寫大寫，和欄位名稱區分。欄位名稱用底線 end_time。

4SQLiteOpenHelper：幫你管理資料庫檔案

Android 內建 SQLiteOpenHelper 類別。我們繼承它（第 9 堂的繼承，像 C# 的 class RecordDb : SQLiteOpenHelper），只要寫兩個方法：

RecordDb.kt
class RecordDb(context: Context) : SQLiteOpenHelper(context, "gyroquiz.db", null, 1) {

    // 第一次使用、資料庫檔案還不存在時執行一次
    override fun onCreate(db: SQLiteDatabase) {
        db.execSQL(
            "CREATE TABLE records (" +
                "id INTEGER PRIMARY KEY AUTOINCREMENT, " +
                "correct INTEGER, wrong INTEGER, duration INTEGER, end_time INTEGER)"
        )
    }

    // 版本號變大時執行：最簡單的做法是砍掉重建
    override fun onUpgrade(db: SQLiteDatabase, oldVersion: Int, newVersion: Int) {
        db.execSQL("DROP TABLE IF EXISTS records")
        onCreate(db)
    }
}
  • (context, "gyroquiz.db", null, 1)：檔名、null（用預設設定）、版本號 1。
  • onCreate：檔案不存在時 Android 自動呼叫一次，在這裡建表。
  • onUpgrade：如果之後你改了表格結構，把版本號改成 2，Android 就會呼叫它。
  • override：覆寫父類別的方法，和 C# 一樣。
  • db.execSQL(…)：執行一句不需要回傳結果的 SQL。
注意
onCreate 只會執行一次！如果建表 SQL 寫錯、改好之後再 Run，因為檔案已經存在，onCreate 不會再跑。解法：模擬器上長按 App → 應用程式資訊 → 清除儲存空間，或把版本號 +1。

5字串接起來要注意空格

SQL 很長，用 + 分成好幾行。每段結尾的逗號和空格很容易漏：

"id INTEGER PRIMARY KEY AUTOINCREMENT, " +   // 結尾有 ", "
"correct INTEGER, wrong INTEGER, …"

漏了空格會變成 AUTOINCREMENTcorrect，Run 時閃退，Logcat 出現 SQLiteException: near "…": syntax error。

6在 App 建立資料庫物件

App.kt（allQuestions 下一行）
val db = remember { RecordDb(context) }

只建立物件還不會產生檔案，要第一次讀或寫時才會呼叫 onCreate。今天為了檢查，暫時加一行：

LaunchedEffect(Unit) { db.writableDatabase }   // 暫時：強迫建立檔案，下堂刪掉

7用 Database Inspector 看資料庫

  1. Run App 到模擬器。
  2. 下方工具列 App Inspection（找不到就用 View → Tool Windows → App Inspection）。
  3. 選 Database Inspector 分頁，左邊會出現 gyroquiz.db → records。
  4. 點 records，可以看到欄位名稱（目前沒有資料）。
小技巧
Database Inspector 是比賽時 debug 資料庫最快的工具，可以直接在裡面打 SQL 查詢。
