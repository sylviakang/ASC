2WinForms 的做法 vs Compose 的做法

在 WinForms 你會拖一個 Timer，Interval = 1000，在 Tick 事件裡 sec++。Compose 沒有 Timer 控制項，而是用 LaunchedEffect 跑一段「可以暫停等待」的程式：

WinForms
timer1.Interval = 1000;
timer1.Tick += (s, e) => {
    sec++;
    label1.Text = sec.ToString();
};
timer1.Start();
Compose
var sec by remember { mutableIntStateOf(0) }
LaunchedEffect(Unit) {
    while (true) {
        delay(1000)
        sec++
    }
}
Text("$sec")
  • LaunchedEffect(Unit) { … }：畫面第一次出現時開始執行裡面的程式，離開這個畫面時自動停止。
  • delay(1000)：等 1 秒。它和 Thread.Sleep 不同，不會讓畫面卡住（這種可以等待的程式叫 coroutine 協程）。
  • sec 是狀態，sec++ 後 Text 自動更新，不用自己設 label.Text。
注意
在 Composable 裡絕對不能用 Thread.sleep，整個 App 會凍住，甚至跳出「應用程式沒有回應」。

3為什麼不用 sec++ 而用毫秒相減

delay(1000) 只保證「至少」等 1 秒，實際可能是 1003、1010 毫秒。跑 10 分鐘後誤差會累積好幾秒。比較準的做法是每次量真正經過多久再加上去：

QuizScreen.kt
var elapsedMs by remember { mutableLongStateOf(0L) }

LaunchedEffect(Unit) {
    var last = System.currentTimeMillis()
    while (true) {
        delay(100)                                  // 等 0.1 秒，不會卡住畫面
        val now = System.currentTimeMillis()
        elapsedMs += now - last                     // 加上「真正經過」的毫秒
        last = now
    }
}
  • System.currentTimeMillis()：現在時間（毫秒）。
  • now - last：這一圈真正經過的毫秒。
  • 每 0.1 秒更新一次，秒數跳動會比較準時。
  • mutableLongStateOf：毫秒數很大，用 Long。

4格式化成 mm:ss

把「格式」寫成獨立的函式放在 Formats.kt，之後結算頁也會用到：

Formats.kt
fun two(n: Int) = n.toString().padStart(2, '0')

// 答題經過時間 mm:ss
fun formatClock(totalSec: Int) = "${two(totalSec / 60)}:${two(totalSec % 60)}"
totalSec/ 60（分）% 60（秒）結果
50500:05
651501:05
731121112:11
  • padStart(2, '0')：不足 2 位前面補 0，像 C# 的 n.ToString("00")。
  • 顯示時：formatClock((elapsedMs / 1000).toInt())，毫秒 ÷ 1000 = 秒。
