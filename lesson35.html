觀念講解

慢慢讀

1寫入一筆資料的 SQL

SQL
INSERT INTO records (correct, wrong, duration, end_time)
VALUES (8, 2, 731, 1782467100000)

id 不用給，AUTOINCREMENT 會自動編號。你可以直接用字串接出這句 SQL 再 execSQL，但容易拼錯、也容易被奇怪的文字弄壞。Android 提供比較安全的方法：ContentValues + insert。

2ContentValues：欄位名稱 → 值

ContentValues 就像 C# 的 Dictionary<string, object>：

RecordDb.kt（加在類別裡）
fun insert(r: GameResult) {
    val values = ContentValues()
    values.put("correct", r.correct)
    values.put("wrong", r.wrong)
    values.put("duration", r.durationSec)
    values.put("end_time", r.endMillis)
    writableDatabase.insert("records", null, values)
}
  • values.put("欄位名稱", 值)：一欄放一次，名稱要和 CREATE TABLE 完全一樣。
  • writableDatabase：取得「可以寫入」的資料庫（第一次會觸發 onCreate）。
  • insert("records", null, values)：表名、null、要放的值。回傳新的 id，失敗回傳 -1。
C#
var values = new Dictionary<string, object>();
values["correct"] = r.correct;
values["wrong"] = r.wrong;
Kotlin
val values = ContentValues()
values.put("correct", r.correct)
values.put("wrong", r.wrong)
注意
欄位名稱打錯（例如 "endtime"）不會編譯錯誤，而是執行時 insert 失敗回傳 -1，Logcat 出現 table records has no column named endtime。

3在哪裡呼叫 insert

成績在 App.kt 的 onFinish 收到，就在那裡存：

App.kt
onFinish = { r ->
    db.insert(r)          // 新增：先存進資料庫
    result = r
    screen = Screen.RESULT
}

上一堂暫時加的 LaunchedEffect(Unit) { db.writableDatabase } 可以刪掉了，insert 會自己打開資料庫。

補充
為什麼不在 QuizScreen 裡存？QuizScreen 只負責「答題」，存檔交給上層，各頁分工清楚。比賽時題本改需求（例如退出也要存）也只要改 App.kt。

4只有完成才存

題本：中途按返回退出，本局不保存。我們的 onExit 只換頁、不呼叫 insert，所以已經符合。這也是確認對話框上寫「本局不會保存」的原因。

5確認有存進去

  1. 玩完一局。
  2. 打開 Database Inspector → records，按重新整理。
  3. 應該看到一列資料，end_time 是一個很大的數字（毫秒）。
  4. 關掉 App（從最近使用清單滑掉）再打開，資料還在。

也可以在查詢框打：

SQL
SELECT * FROM records
